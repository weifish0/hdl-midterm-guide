模擬與 Testbench

A、B 題的分數是 testbench 給的。看懂它怎麼餵資料、在哪一拍比對，你就知道自己的電路該在哪一拍出答案。

Testbench 是什麼

一個沒有 port 的模組：在裡面產生時脈、餵輸入、檢查輸出。它只拿來模擬，不會合成，所以可以用 #延遲、initial、$display 這些「軟體」寫法。

`timescale 1ns/1ps                 // #1 = 1 ns
module adder_tb;
    logic       clk = 0, rst;
    logic [7:0] a, b;
    logic [8:0] sum;

    adder8 dut (.a(a), .b(b), .sum(sum));   // 被測電路 (Design Under Test)

    always #5 clk = ~clk;          // 每 5 ns 翻一次 -> 週期 10 ns (100 MHz)

    initial begin
        a = 8'd200; b = 8'd100;
        #10;                        // 等 10 ns
        $display("sum = %0d", sum);
        @(posedge clk);             // 等到下一個上升緣
        @(negedge clk);             // 等到下一個下降緣
        repeat (3) @(posedge clk);  // 等三個上升緣
        $finish;                    // 結束模擬
    end
endmodule

為什麼在 negedge 改輸入、在 negedge 檢查？

如果剛好在上升緣同時改輸入，模擬器不保證 flip-flop 拿到的是舊值還是新值（race condition）。在下降緣（兩個上升緣正中間）改輸入、看輸出最安全。Lab 2 advanced 的 testbench 規定「只在 negedge 改輸入」就是這個原因。

常用系統函式

寫法用途
$display("x=%0d y=%b z=%h", x, y, z)印一行。%d 十進位、%0d 不補空白、%b 二進位、%h 十六進位、%t 時間
$monitor("...", ...)訊號一變就自動印
$time目前模擬時間
$finish結束模擬
$signed(x)把 x 當成有號數（印負數時用）
$readmemb / $readmemh從檔案讀二進位 / 十六進位到陣列
$fopen / $fscanf / $fclose一行一行讀檔

Pattern 檔：輸入與答案

考試的 pattern 檔每一行是一組「輸入 + 正確答案」。看懂格式，就能自己手算驗證。

$readmemh：2023 A 題

3_ae_f3_fe84
0_17_d3_fbf8
2_78_70_ffff
reg [35:0] mem [0:998];
$readmemh("pattern_A.dat", mem);       // 每行一個元素，底線會被忽略
{ctrl, A, B, ans} = mem[i][33:0];       // 2 + 8 + 8 + 16 = 34 bits

手算第二行：ctrl = 0（A*B+3），A = 0x17 = 23，B = 0xd3 = 211 → 有號 -45。23 × (-45) + 3 = -1032 = 16'hfbf8 ✔。

空白會切斷$readmemh 用空白分隔元素。3 ae f3 fe84 會被讀成四個元素，要用底線 3_ae_f3_fe84。

$fscanf：2023 B 題

010101111001 01011111 111
000101111101 01011111 111
file = $fopen("pattern_B.dat", "r");
$fscanf(file, "%b %b %b", data, decoded_ans, ans);

Lab 2 practice 的格式

logic [24:0] patterns [0:31];
$readmemb("pattern_A_practice.dat", patterns);
{expected_rst, A, B, expected_out} = patterns[i];

比對答案

integer err = 0;
...
@(negedge clk);
if (out !== expected) begin          // 用 !== 才抓得到 X 和 Z
    err = err + 1;
    $display(" A=%0d B=%0d out=%0d expected=%0d", A, B, $signed(out), $signed(expected));
end
...
if (err == 0) $display("ALL PASS");
!= 與 !==out != 5 在 out 是 X 時結果是 X（if 當成 false，錯誤被放過）。out !== 5 逐位元比較 0/1/X/Z，X 一定不等於 5。testbench 都用 !==。

用 task 包裝重複的步驟

task automatic write_mem(input [6:0] addr, input [3:0] data);
    @(negedge clk);
    we = 1; w_addr = addr; din = data;
    @(negedge clk);
    we = 0;
endtask

initial begin
    write_mem(7'h5A, 4'd4);
    write_mem(7'h01, 4'd5);
end

看波形除錯

  • Scope 視窗選 dut，把內部訊號（state、counter）拖進波形視窗。
  • Radix 改成 Signed Decimal 看有號數。
  • 從第一個錯誤的 pattern 開始往回看：輸入對嗎？組合結果對嗎？暫存器有在正確的邊緣更新嗎？

拆解 2023 A 題的 testbench

這段決定了你的電路要「晚一拍」輸出。

// 餵資料：每個 posedge 後 1 個時間單位換下一組
for (feed_i = 0; feed_i < PATTERN_NUM; feed_i = feed_i + 1) begin
    @(posedge clk);
    #1;
    {last_ctrl, last_A, last_B, last_ans} = {ctrl, A, B, ans};  // 記住「上一組」
    {ctrl, A, B, ans} = mem[feed_i][33:0];                       // 換新的
end

// 檢查：每個 negedge 比對 out 和「上一組」的答案
@(negedge clk);
for (fetch_i = 0; fetch_i < PATTERN_NUM - 1; fetch_i = fetch_i + 1) begin
    @(negedge clk);
    if (out !== last_ans) ...    // ← 比的是 last_ans
end
如果你用 assign 直接輸出out 會在輸入一變就變成 f(P1)，但 testbench 比的是 ans0 → 全部 FAIL。所以 A 題一定要有 always_ff 那一級。

2023 B 題的 testbench 結構完全一樣（比對 last_decoded_ans、last_ans），所以 B 題的 decoded 和 out 也要暫存。

reset 怎麼測

testbench 先把輸入設成 Z、拉 rst 10 個週期，再放開。Lab 2 的 testbench 還會在「兩個上升緣中間」拉 reset，檢查你是不是同步 reset（非同步會立刻變 0 → FAIL）。
